Privacy Policy

This policy describes information Nina2.0's operator stores in the bot's local database and uses to operate the bot, dashboard, and leaderboards. Discord separately processes information under its own privacy policy.

Information collected or generated by Nina2.0

  • Discord account details: your Discord user ID, username, and display name are saved locally when you use a command or a tracked message interaction.
  • Command activity: command name, submitted command options, user ID, server and channel IDs where available, timestamp, status, captured bot response, and error details are saved locally. Error records can include diagnostic traceback text.
  • Trigger and interaction records: event type and metadata such as user, server, channel, timestamp, and relevant command or interaction identifier are saved locally. The core bot records that a DM arrived, but does not save the DM's message text. It also records bot mentions and replies to the bot without saving the message text.
  • Access roles: whether the owner has marked an account as blacklisted, staff, or special, along with the role assignment time, is saved locally.
  • Live operational information: the dashboard receives the bot's current server list and server member counts where available, plus measurements such as CPU, memory, disk, uptime, and supported power telemetry. The core reports these as live operational data rather than writing them to its activity database.

Module authors may add features that collect additional information. Those features should explain their data practices separately; the core's behavior does not guarantee what an independently developed module stores.

Why information is used

  • To execute and troubleshoot commands and maintain the service.
  • To enforce blacklist, staff, special-user, and owner-only access rules.
  • To calculate command and user leaderboards from eligible successful commands and to provide the owner with broader operational statistics.
  • To display recent activity, error details, server information, and system measurements in the password-protected owner dashboard.
  • To diagnose failures, protect the service, and respond to support requests.

Who can see information

The bot operator can access the local database and the password- protected dashboard, including user identities, command options, responses, and error details. Eligible leaderboard totals and names may be visible to people who visit the public leaderboard. Error notices and owner details may be posted publicly in the channel where a command fails. Treat command options and channel messages as potentially visible to others; do not submit secrets or sensitive personal information.

Discord receives information necessary to deliver bot interactions. When the website is exposed through ngrok, website traffic passes through that service. These providers process data under their own policies. Nina2.0's core dashboard uses a WebSocket for live updates instead of repeatedly polling the website; normal page loads and login submissions still use HTTP.

Storage and retention

The core stores its records in a SQLite database on the machine where Nina2.0 runs. The core does not automatically delete command, user, role, or trigger records on a fixed schedule. They may remain until the operator removes them or deletes the database. Backups, if made by the operator, may retain copies separately. The operator should restrict access to the machine, database, backups, environment configuration, and dashboard password.

Security

The dashboard is protected by a password and session cookie, and its live data stream requires an authenticated dashboard session. No internet-connected service can be guaranteed completely secure. Users should avoid placing passwords, payment details, authentication tokens, or other secrets in command options or messages.
